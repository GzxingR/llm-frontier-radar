站点没说的模型，自己撞出来。

中转站常有两种情况，官方页面都不告诉你：模型能用但没列出来，或者列出来了其实不能用。Frontier Radar 拿一份固定候选池逐站去撞，把「宣称」和「实际」做差集。

View on GitHub 看判定逻辑

隐藏可用

能真实调用，但 /v1/models 和价目表里没有。这是雷达最想找的东西。

公布但坏

站点列了模型，实际 404、接口停用、或者根本不出字。省下瞎试的时间。

零 token

默认只做参数校验级探测，不进入推理。真实调用单独开关，默认关。

判定不是二分，是八种

最容易做错的地方，是把「这个 key 用不了」当成「模型不存在」。所以每个结论都要求证据强度。

标签含义证据要求
隐藏可用能用，站点没列参数校验拦住，或真实调用成功
已公布可用列了，确实能用同上 + 在站点列表里
公布但坏列了，但不可用明确 model_not_found
不存在没列，也确实没有明确 model_not_found
分组没有这个 key 的分组没有它站点分组提示，不等于不存在
无权限 / 限流403 / 429HTTP 状态码
待确认超时、5xx、413证据不足，不判死
「分组没有」和「不存在」是两个结论。前者换把 key 可能就有了，雷达不会替你判死。

三级探测，协议自动回退

级别手法成本默认
L1 存在性空 messages 打 /chat/completions，让参数校验拦下0 token开
L2 协议自适应站点停用 chat 接口时，自动换 /v1/responses 重试0 token开
L3 真实性max_tokens: 1 真实小请求会花 token关
有些站悄悄停用了 /v1/chat/completions 只留 /v1/responses。不自动换协议，会把好模型误判成坏的。

快速开始

git clone https://github.com/GzxingR/llm-frontier-radar.git
cd llm-frontier-radar
cp config.example.json config.local.json
node server.js
# 打开 http://127.0.0.1:5199
# 点「设置」加站点和 key → 点「开始扫描」

零运行时依赖，Node 20+。定时扫描按小时设，界面显示倒计时。

不会把站点撞挂

密集 404 请求看起来就像扫描器。所以同站串行、请求间留间隔、带 ±40% 随机抖动、站间也留间隔，定时最小按小时计。这些都能调，但别调到 0 —— 被 WAF 拉黑比慢更麻烦。
